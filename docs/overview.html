Get started in five steps

From source code to the first board in the browser.

1
Build
go build -o bin/kard \ ./cmd/kard
Needs Go 1.27. Then put bin/kard in your PATH. Or take a ready file from scripts/dist.
2
Check who you are
kard whoami alex.berger@example.com (from git config user.email)
Nothing to set up: the name comes from Git, per repo. A name of your own with kard whoami --set.
3
Create a board
cd ~/Repos/project kard init board
Writes board.yaml and registers the board.
4
Find more boards
kard scan ~/Repos kard boards
Keeps looking for board.yaml, six levels deep.
5
Work
kard ui kard new "Check login" kard take check-login
Browser and terminal act the same, with the same rules.
kard init · empty folder
board/ (empty)
→
board/ board.yaml backlog/ working_on/ doing done/ done
Three columns by default. Your own with --columns a,b,c.
kard init · existing notes
notes/ ideas/*.md wip/*.md closed/*.md
→
notes/ board.yaml ideas/ wip/ doing closed/ done
Folders become columns. No file is changed. kard lint then shows what does not fit.

Short name or address. Two letters from the name in Git; your own monogram is filled with ink. The tooltip shows name and address. .mailmap merges old and new addresses.
Assign · without typing addresses
kard assign export-als-pdf ort assignee = sam.ortmann@example.com kard assign export-als-pdf a kard: "a" fits 2 people: alex.berger@example.com (Alex Berger), anna@example.com (Anna Lang)
kard searches the board's commit authors and the people on its cards, by the beginning of address or name, ignoring accents. No match: a valid name counts as a new person.

Three levels of Git

One line in board.yaml decides.

sync: none
Board inside the code repo. You commit yourself.
sync: commit
A board repo of its own, alone.
sync: push
A team's board repo. Whoever pushes first wins; the other learns where the card is now.
